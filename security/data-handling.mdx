## Encryption

### In Transit

All data is encrypted in transit using TLS 1.2 or higher:

- **Agent → Backend:** The agent's HTTP client enforces `MinVersion: TLS 1.2`. Connections to plain HTTP are rejected.
- **Dashboard → Backend:** HTTPS enforced via ALB with automatic HTTP→HTTPS redirect. HSTS headers instruct browsers to always use HTTPS (`max-age=31536000`).
- **Backend → Database:** PostgreSQL connections use `sslmode=require`.

### At Rest

- **Database:** AWS RDS with AES-256 encryption using AWS-managed keys. All tables — including scores, audit entries, API key hashes, and integration configs — are encrypted on disk.
- **API Keys:** Stored as bcrypt hashes, not reversible. The plaintext key exists only in memory during the initial creation response.
- **Integration Tokens:** GitLab tokens are stored encrypted in the database; GET responses mask tokens (first 4 + last 4 characters visible). GitHub stores no customer token at all — the integration is a GitHub App installation, and each workflow run authenticates with a short-lived identity token GitHub issues to it.

## Data Retention

Snapshot data is held in memory and replaced every 10 seconds when the agent pushes a new snapshot. Only the latest snapshot per cluster is retained.

Score history is persisted in PostgreSQL and retained indefinitely. You can export score history and full cluster reports as CSV or JSON at any time from the dashboard.

Audit trail entries are retained indefinitely and can be exported for compliance review.

Engineering Opinions, incident workspace conversations and decisions, Code Graph snapshots and the incident embeddings behind Engineering Experience are tenant data in the same database, under the same encryption and row-level isolation. The Code Graph keeps the five most recent snapshots per repository and prunes older ones.

## Data Minimization

ChangeGuard AI follows a principle of data minimization — it collects only what's needed to calculate the CSC score and surface risks:

- **Metadata only:** Resource names, status, counts, and configurations — not data contents
- **No secrets:** Secret values, environment variables, and ConfigMap data are never read
- **No application data:** Persistent volume contents and network payloads are never read, and source code is never sent to ChangeGuard AI. With the optional [Code Graph](/investigate/code-graph), an indexer you run in your own cluster reads the repositories you list and ships only the derived graph (symbol names, file paths, relations and the commit SHA); the source and the clone credential stay in your cluster
- **Configurable logging:** Pod log collection is off by default and only enabled when you choose to turn it on

## Engineering intelligence and investigation

The November 2026 releases added capabilities that use AI models and, optionally, your repositories. This section states what each one reads, where it runs and what it keeps. The behaviour of each is on its own page: [Engineering intelligence](/intelligence/overview), [Incident workspace](/investigate/incident-workspace) and [Code Graph](/investigate/code-graph).

### Judgment and execution make no model call

SHIP / HOLD / BLOCK, the CSC Score, Permits, execution and verification are deterministic and never call a model. The AI participant in the incident workspace holds no credentials and executes nothing; execution still flows only through the remediation engine, its policy checks and a [Permit](/govern/permit). An AI result is advice with provenance, never an authorization.

### AI models on Amazon Bedrock

Every AI capability reaches Amazon Bedrock through one router in the control plane: Anthropic Claude as the preferred model and Kimi K3.1 (Moonshot AI) as a permanent, evaluated fallback, both on Amazon Bedrock with US cross-Region inference (us-east-1, us-east-2, us-west-2). Amazon Bedrock does not share prompts or outputs with the model providers, and neither AWS nor the providers use them to train models. ChangeGuard AI has not enabled Bedrock model-invocation logging, and prompts are never written to ChangeGuard AI's logs. Which operations the fallback serves, and what you see when no model can answer, are on [Model availability](/intelligence/model-availability).

### What the models see

| Capability | Sent to the model | Never sent |
| --- | --- | --- |
| Engineering Advisor | The environment's current state and recent record (evidence from Fleet or Edge) | The diff of the change |
| Engineering Opinion, Reasoning, Experience | The root-cause analysis, its cited evidence and any recalled experience from your own workspace | The raw diff, Secret values, source code |
| Incident workspace (`@changeguard-ai` replies, summaries) | The incident's record and the conversation it is asked about | Anything outside that incident |
| Root-cause analysis | The incident's evidence and, where a repository is indexed, the Code Graph as the code behind the change | Source code |

### Tenant memory (Engineering Experience)

Engineering Experience recalls your workspace's own history: terminal outcomes of past fixes on the same target, and strongly similar past incidents found by comparing stored embeddings. The embeddings are computed on Amazon Bedrock, stored per tenant under the same row-level security as everything else, and deleted with the tenant. Memory is retrieval, not retraining: no model, threshold, policy or prompt is modified by an outcome, and one tenant's history never informs another's.

### Code Graph

Off until you enable `codeGraph.enabled` in the Edge chart. The indexer is a CronJob in your cluster, pinned to a verified deterministic release and running as non-root with all capabilities dropped. It clones the repositories you list with a credential you hold (an HTTPS token or an internal mirror) and posts only the graph to `POST /api/ingest/codegraph` with the environment's agent key, under the same enrollment boundary as every other ingest. Nothing about the credential leaves the cluster. Graphs are stored per tenant under row-level security, capped at 32 MiB each with five snapshots per repository; a graph with no nodes or with id-less nodes is rejected and never replaces a good snapshot. Turning the Code Graph off in **Settings → Engineering assistance** stops ingest, queries and the code context in root-cause analysis.

### Incident workspace

Any signed-in member of the tenant can read the workspace, comment, reply and mention; a comment's author is always the authenticated user, never a field in the request, and only the author can edit it. Humans can post only ordinary comments: the AI's post kinds (observations, recommendations, replies, summaries) cannot be forged by a person, and the AI can never be the accountable owner. A mention of `@changeguard-ai` on a plan without the AI participant is recorded and never enqueued, so no model call is spent. An admin can turn the workspace off for the whole tenant, and the change is audited.

### Customer control and audit

**Settings → Engineering assistance** holds six switches (Advisor, Opinion, Reasoning, Experience, incident workspace, Code Graph), admin only; every change is audited with who made it. Every AI result and its audit row record the model that answered, its provider and role (primary or fallback), why the fallback was used, the prompt version, token usage, latency, a correlation id and the Bedrock request ids. Customers see plain words and a reference; provider error text stays in ChangeGuard AI's operational logs.

## Data Deletion

When you delete your account or a cluster is removed:

- Cluster snapshot data is removed from memory immediately
- Score history, audit entries, and configuration are deleted from the database via cascading foreign key constraints
- API keys associated with the tenant are permanently deleted

The production database keeps encrypted automated backups for disaster recovery with a 14-day retention period, so rows deleted from the database can persist in those backups for up to 14 days before they age out. Backups restore the whole database to a point in time; there is no per-tenant restore. Full-tenant erasure, including the data of the engineering-intelligence and investigation capabilities, goes through [support](mailto:support@changeguard.ai).
