ChangeGuard AI is the **decision and control layer for infrastructure change**. Before a change executes, it judges the proposed change against the environment it will actually enter and answers **SHIP**, **HOLD** or **BLOCK**, with the reasons. When a change is authorized — by a person, or by a policy you wrote — that authority becomes a short-lived **ChangeGuard Permit**. An **Executor** carries out only the permitted action. Then ChangeGuard observes what actually happened, attributes it to the change, and verifies the outcome against fresh evidence.

```text
PROPOSE → IDENTIFY → UNDERSTAND → JUDGE → AUTHORIZE → PERMIT → EXECUTE → OBSERVE → ATTRIBUTE → VERIFY → RESPOND
```

Or, in short: **Judgment → Permit → Execution → Outcome.**

Infrastructure is now changed by humans, CI/CD, automation and AI agents, and every change arrives with a green build. Existing authorization answers _"can this actor make the change?"_ ChangeGuard answers _"should this exact change happen in this exact environment right now?"_ — and then _"did reality match the judgment?"_ AI can make the change. ChangeGuard decides whether it should.

## Four things, kept apart on purpose

|  | What it is | What it is not |
| --- | --- | --- |
| **Judgment** | What ChangeGuard believes about this change, here, now — SHIP, HOLD or BLOCK, with the evidence it had and did not have | An authorization. A verdict grants nothing. |
| **Permit** | What is authorized: a signed, single-use token bound to this action, this target, this environment, this approval or policy, and this time window | An API key, a session, a standing grant, or a blanket permission for AI |
| **Executor** | What acts: the Cloud Executor (nothing to install) or a Local Executor, with a per-environment least-privilege identity | Something that decides. The Executor never authorizes anything. |
| **Observation** | What proves what happened: fresh evidence from the environment, attributed to the change by identity | An assumption. No observation, no VERIFIED. |

**Autonomous-capable by design. Human-controlled by default.** Every environment starts in **Advise**: ChangeGuard can diagnose, prepare and execute, but a human authorization must exist before anything executes. **Auto** is opt-in and acts only inside an explicit policy; outside it, Auto falls back to Advise. See [Advise and Auto](/autonomy/autonomy-model).

## Where it runs today

Kubernetes on **AWS EKS** is the current wedge. **Fleet** reads your environments centrally with read-only access you authorize — nothing to install. **Edge** is an optional in-cluster collector for evidence that must stay local; it is never required for judgment or execution. The **Executor** is the governed action plane. See [Fleet, Edge and the Executor](/connect/fleet-edge-executor).

## How we label claims

Every capability in these docs is one of:

| Label | Meaning |
| --- | --- |
| **Live** | Running in production for every tenant (plan gating noted where it applies) |
| **Live-proven** | Running in production _and_ exercised end to end by production acceptance and continuous security testing — the Permit, the Cloud Executor, per-environment execution identity |
| **Supported** | Available and used where the topology calls for it — the Local Executor, ChangeGuard Edge |
| **Early Access** | Real, off by default, on request — the Engineering Advisor and related reasoning capabilities |
| **Roadmap** | Planned, not shipping — Realms, SSO/SAML, self-hosted inference for judgment and reasoning |
| **Vision** | Direction, not a feature — governed autonomous change beyond Kubernetes |

Nothing emerging is documented as if it ships today. See [Core concepts](/concepts/overview) and [Known limitations and roadmap](/concepts/limitations-and-roadmap).
